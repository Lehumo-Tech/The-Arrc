     9→## ◆ Design Philosophy
    10→
    11→**"New Generation, New Direction."**
    12→
    13→The ARRC design system is built to make a young political movement feel **modern, trustworthy, and rooted in South African identity**. Three principles guide every visual decision:
    14→
    15→1. **Institutional gravitas.** A new party must look established. We borrow the visual language of legacy institutions — serif display type, gold leaf, deep navy — but execute them with modern tools (glassmorphism, 3D tilt, scroll-driven motion).
    16→2. **African identity, not African stereotype.** The colour story is anchored in the South African flag (navy, green, gold, red, white). Cultural texture is referenced through Ndebele/Zulu-inspired geometric patterns — abstract diamonds, not literal motifs — applied sparingly as background texture.
    17→3. **Premium without elitism.** The party's value proposition is R20 membership for everyone. The visual quality must signal "this is a serious movement" while never feeling exclusive or corporate. Glassmorphism and gold accents communicate aspiration; warm cream backgrounds and rounded corners keep it approachable.
    18→
    19→The result is a palette of **gold (#d4a843) + deep navy (#0a1628) + warm cream (#faf8f2)**, executed with Cormorant Garamond for headlines and Geist for body, animated with Framer Motion, and accented with 3D tilt and shimmer effects.

   129→### Colour Usage Guidelines
   130→
   131→- **Gold (#d4a843)** is the singular accent colour. Never use blue/red/green as accents except in `.sa-stripe`.
   132→- **Navy (#0a1628)** is the primary dark surface. Pair with `.glass-dark` overlays for content.

   134→- **Emerald** is reserved for success states (donation completed, member active) and the SA flag stripe.

   178→

   182→

   186→- Font variables (`--font-geist-sans`, `--font-geist-mono`, `--font-heading`) applied to `<body>` in `layout.tsx`.

   236→## ◆ Component Patterns
   237→
   238→### Glassmorphism
   239→
   240→Two variants, used strategically:
   241→
   242→#### `.glass` — Warm Translucent
   243→```css
   244→background: rgba(255, 248, 230, 0.06);   /* warm cream tint */
   245→backdrop-filter: blur(20px);
   246→border: 1px solid rgba(212, 168, 67, 0.12); /* gold border */
   247→box-shadow: 0 8px 32px rgba(0, 0, 0, 0.12);
   248→```
   249→**When to use:** Over light or warm backgrounds (`bg-arrc-warm-section`, `bg-arrc-gold-section`). Used on hero CTAs, About value cards, FAQ accordion.
   250→
   251→#### `.glass-dark` — Navy Translucent
   252→```css
   253→background: rgba(10, 22, 40, 0.6);  /* navy tint */
   254→backdrop-filter: blur(20px);
   255→border: 1px solid rgba(255, 255, 255, 0.08);
   256→```
   257→**When to use:** Over dark backgrounds (`bg-arrc-dark-section`, hero overlay). Used on chat assistant panel, cookie consent banner, footer columns.
   258→
   259→### 3D Tilt Cards
   260→
   261→A two-class system for mouse-driven perspective tilt:
   262→
   263→```html
   264→<div class="perspective-container">      <!-- perspective: 1200px -->
   265→  <div class="tilt-card">                 <!-- transform-style: preserve-3d -->
   266→    <div style="transform: translateZ(20px)">…</div>
   267→  </div>
   268→</div>
   269→```
   270→
   271→- `.perspective-container` sets `perspective: 1200px` on the parent.
   272→- `.tilt-card` sets `transform-style: preserve-3d` and `transition: transform 0.3s ease-out`. On hover: `transform: translateZ(20px)` lifts the card.
   273→- For mouse-driven `rotateX/rotateY` (used in About value cards, Gallery items), components compute rotation from `event.clientX/Y` relative to card center via Framer Motion's `onMouseMove` and apply via `motion.div` style.
   274→
   275→### Premium Cards (`.card-premium`)
   276→
   277→A 4-layer shadow system with hover lift:
   278→```css
   279→box-shadow:
   280→  0 1px 2px rgba(0,0,0,0.04),     /* tight contact shadow */
   281→  0 4px 8px rgba(0,0,0,0.04),     /* near depth */
   282→  0 12px 24px rgba(0,0,0,0.06),   /* mid depth */
   283→  0 24px 48px rgba(0,0,0,0.04);   /* far ambient */
   284→```
   285→On hover: shadows deepen to 5 layers + 1px gold ring (`rgba(212,168,67,0.15)`) + `translateY(-4px)` lift. Transition: `0.4s ease`.
   286→
   287→Variant `.card-premium-dark` for use on dark sections — replaces background with `rgba(255,255,255,0.03)` + `backdrop-filter: blur(20px)`.
   288→
   289→### Photo Frames (`.photo-frame`)
   290→
   291→A two-pseudo-element frame:
   292→- `::before` — inset 8px gold border (`rgba(212,168,67,0.2)`), `border-radius: 0.75rem`. Sits at `z-index: 2`.
   293→- `::after` — bottom 40% gradient overlay (`rgba(10,22,40,0.6) → transparent`) for caption legibility. Sits at `z-index: 1`.
   294→
   295→Used on NEC photos, gallery images, hero image.

   309→### African Pattern (`.african-pattern`)
   310→
   311→Ndebele/Zulu-inspired diamond geometry. Two definitions exist in `globals.css` (see Known Tech Debt — second overrides first):
   312→
   313→The active definition uses 4 layered `linear-gradient` patterns at 135°, 225°, 45°, 315° — each adding `rgba(212,168,67,0.03-0.04)` at 25% positions on a 40×40px grid. Result: a subtle diamond grid that reads as African textile texture without being literal.
   314→
   315→**When to use:** Section background overlay on dark surfaces (`.bg-arrc-dark-section` already includes a variant). Never on light sections (too visually busy).
   316→
   317→### Depth Shadow (`.depth-shadow`)
   318→
   319→A 4-layer shadow with a subtle gold ambient:
   320→```css
   321→box-shadow:
   322→  0 4px 6px -1px rgba(0,0,0,0.10),
   323→  0 10px 15px -3px rgba(0,0,0,0.08),
   324→  0 20px 25px -5px rgba(0,0,0,0.06),
   325→  0 0 40px -10px rgba(212,168,67,0.15);
   326→```
   327→Used on cards that need to "float" — chat panel, CRM modals, hero feature tiles.
   328→
   329→### Hero Overlay (`.hero-overlay`)
   330→
   331→A 3-stop diagonal gradient over hero imagery:
   332→```css
   333→linear-gradient(135deg,
   334→  rgba(10, 22, 40, 0.92) 0%,      /* deep navy left */
   335→  rgba(30, 64, 175, 0.80) 50%,    /* ARRC blue mid */
   336→  rgba(10, 22, 40, 0.88) 100%);   /* deep navy right */
   337→```
   338→Guarantees text legibility on any hero image.
   339→
   340→### Badge (`.badge-premium`)
   341→
   342→Pill-shaped (`border-radius: 100px`), `padding: 4px 14px`, `font-size: 0.75rem`, uppercase, letter-spacing 0.05em. Used for status indicators (e.g. "President", "Active Member", "Urgent").

   371→| **3D tilt on hover** | `whileHover: {rotateY: 6, rotateX: -2, scale: 1.02}` | 0.3s | spring | About image card, premium tiles |
   372→| **Card lift on hover** | `whileHover: {y: -8}` + shadow expand | 0.3s | spring | Policy cards, news cards |
   373→| **Image parallax** | `useScroll + useTransform: y: [-20, 20]` | scroll-driven | linear | Policy card images |
   374→| **Modal entrance** | `initial: {opacity:0, scale:0.95}` → `animate: {opacity:1, scale:1}` | 0.2s | easeOut | Legal modals, CRM dialogs |
   375→| **Sheet drawer** | slide-in from left/right | 0.3s | easeInOut | Mobile navigation |
   376→
   377→All Framer Motion transitions honour `prefers-reduced-motion: reduce` — animations degrade to instant state changes.

   451→## ◆ Accessibility
   452→
   453→### WCAG 2.1 AA Compliance
   454→
   455→- **Semantic HTML:** `<main>`, `<nav>`, `<footer>`, `<section>`, `<article>`, `<aside>` used appropriately. Heading hierarchy (h1 → h2 → h3) never skips levels.
   456→- **ARIA:** All interactive non-text elements (icon buttons, modals, drawers, tabs, accordions) have `aria-label` or `aria-labelledby`. Modal focus traps via Radix UI primitives.
   457→- **Keyboard navigation:** Tab order follows visual order. All interactive elements reachable and operable via keyboard. `Enter` activates links/buttons; `Esc` closes modals/drawers.
   458→- **Focus visibility:** `.focus-gold:focus-visible` applies a 2px solid `rgba(212,168,67,0.6)` outline with 2px offset. Never `outline: none` without replacement.
   459→- **Screen reader-only content:** `.sr-only` utility class for labels that are visual-only (e.g. icon button purposes).
   460→- **Form labels:** Every `<input>` has an associated `<label>` (via React Hook Form's `<label htmlFor={id}>` pattern).
   461→

   464→| Foreground | Background | Ratio | Standard | Pass |

   483→## ◆ Liquid Glass & Bento Grid (NEW — Upcoming v3.0)
   484→
   485→The next major design language upgrade introduces two interrelated visual systems:
   486→
   487→### Liquid Glass Surfaces
   488→
   489→A modernisation of the existing glassmorphism pattern. Where `.glass` and `.glass-dark` use a flat translucent background + blur, **liquid glass** adds:
   490→
   491→- **Refraction** — content behind the surface appears subtly distorted (like looking through water), implemented via WebGL shaders.
   492→- **Beveled edges** — inner highlights and shadows on the surface border simulate physical glass thickness.
   493→- **Specular highlights** — a moving light reflection that tracks pointer position.
   494→- **Depth layering** — multiple glass surfaces at different `translateZ` depths create a 3D stacked effect.
   495→
   496→**Implementation plan:** Use the `build-webgl-liquid-glass` skill to generate the WebGL shader component. Apply to:
   497→- Hero CTA cards (primary surface)
   498→- CRM dashboard stat cards
   499→- Chat assistant panel
   500→- Membership tier highlight
   501→
   502→**Performance budget:** Liquid glass surfaces must render at 60fps on mid-range mobile. Fallback to current `.glass` if WebGL unavailable.
   503→
   504→### Bento Grid Layouts
   505→
   506→A move away from uniform card grids toward **varied cell sizes** that emphasise hierarchy:
   507→
   508→```
   509→┌──────────┬──────────┬─────────┐
   510→│          │          │         │
   511→│  LARGE   │  MEDIUM  │  SMALL  │
   512→│  (2x2)   │  (2x1)   │  (1x1)  │
   513→│          ├──────────┤         │
   514→│          │  MEDIUM  │  SMALL  │
   515→│          │  (2x1)   │  (1x1)  │
   516→├──────────┴──┬───────┴─────────┤
   517→│   WIDE      │    TALL         │
   518→│   (4x1)     │    (2x3)        │
   519→│             │                 │
   520→└─────────────┴─────────────────┘
   521→```
   522→
   523→**Application targets:**
   524→- Home "Highlights" section — currently uniform tiles, becomes bento with featured items spanning 2×2.
   525→- Donate campaigns grid — featured campaign gets the large cell; others fill medium/small.
   526→- CRM dashboard — stat cards become bento with primary KPI in large cell.
   527→
   528→**Implementation plan:** Use the `bento-grid` skill to generate responsive CSS Grid templates. Cells use named grid areas that reflow at each breakpoint.
   529→
   530→**Mixed content types:** A single bento grid may mix:
   531→- Stat cards (numeric + chart)
   532→- Image tiles (photo + caption)
   533→- Action cards (icon + CTA)
   534→- Quote blocks (large serif text)
   535→- Live data widgets (donation progress, member count)
   536→
   537→This variety prevents the visual monotony of uniform card grids and lets designers direct attention to the most important content via cell size.
   538→
   539→### Migration Path
   540→
   541→The v3.0 upgrade is additive — existing `.glass` and standard grids remain for sections that don't benefit from the new patterns. Liquid glass and bento are applied selectively to:
   542→1. Hero (immediate visual upgrade)
   543→2. Home highlights (information hierarchy)
   544→3. CRM dashboard (data density)
   545→
   546→All existing components continue to function unchanged.

   553→
   554→### Token Foundation (Already Complete)

   560→1. Wrap `<html>` in `<ThemeProvider attribute="class" defaultTheme="dark" enableSystem>` in `layout.tsx`.

   562→3. Add a theme toggle to the navigation bar (sun/moon icon, top-right).
   563→4. Persist preference in `localStorage` (handled automatically by next-themes).
