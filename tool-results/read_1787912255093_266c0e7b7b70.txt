     3→     3→ *
     4→     4→ * This module contains the same content that `auto-seed.ts` writes into the
     5→     5→ * SQLite database (news, videos, events, leaders, policies, gallery, FAQs,
     6→     6→ * values, documents). It is pure data with no DB dependency.
     7→     7→ *
     8→     8→ * Why this exists:
     9→     9→ *   The public site fetches content from `/api/content`, which reads from the
    10→    10→ *   local SQLite database. On sandbox / writable-filesystem deployments the DB
    11→    11→ *   is auto-seeded and everything works. But on read-only / serverless
    12→    12→ *   deployments (e.g. Vercel) the SQLite file cannot be created or written, so
    13→    13→ *   the DB stays empty and `/api/content` would return empty arrays — meaning
    14→    14→ *   the live site would show NO news, NO videos, NO events.
    15→    15→ *
    16→    16→ *   To guarantee the live site always shows all news & media, `/api/content`
    17→    17→ *   falls back to `getStaticContentSnapshot()` (this module) whenever the
    18→    18→ *   database is unavailable or returns no rows.
    19→    19→ *
    20→    20→ * `auto-seed.ts` imports these arrays so the DB-seeded content and the static
    21→    21→ * fallback never drift apart.
    22→    22→ */
